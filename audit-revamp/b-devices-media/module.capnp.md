# audit: `schema/module.capnp` (418 lines)

## Verdict
**FIX (targeted) — trim the scope, fix the authority model.** module.capnp's core is sound and should be kept: `LoadSpec`/`Source` (a union of builtin/blob/url/manifest/wasm, so no serialization format is frozen — module.capnp:127-137), `T.DataHandle` for payload blobs, `T.Error` in `ModuleFailure.reason`, `T.Pagination` on `list`, `cancel` on the subscription, `Manifest`/`Semver` imported from the canonical manifest schema, and `ModuleEventEntry.payload :Data` as an opaque event payload. Against that, the file has accumulated three things that do not belong in a module-loading contract: (1) an **authority model that contradicts the doctrine twice** — `LoadSpec.capabilities @2 :List(Text)` grants authority by *name string*, and `ModuleLifecycleHook.command @2 :List(Text)` is an unauthenticated command execution path, the exact anti-pattern ai.capnp:324-327 removed from its own schema; (2) **an application marketplace** with ratings/download counts and matching install, A/B feature flags, and multi-tenancy configuration — none of which is an interop contract between a module and its host; and (3) `ModuleProfile.topFunctions :List(ModuleFunctionProfile)` with function names, which is the `LogSource {file, line, function}` anti-pattern DESIGN_PRINCIPLES.md:228 already rejects. Trim (1)-(3), keep the rest.

## Wire-breakers
- **None.** No compile errors, no ordinal collisions (verified mechanically).
- `module.capnp:121` — `LoadSpec.capabilities @2 :List(Text)` with the comment "Pre-allocated capability grant to give to the module". `T.CapabilityId` exists (types.capnp:937) and `ModuleState.grantedCapabilities @7 :List(T.CapabilityId)` exists (module.capnp:93) — so the load path grants by **name string** and the state path reports by **UInt64 id**, two representations of the same authority, and neither is a `Capability` reference. A 2046 host cannot express *which* capability was granted (operations, constraints, expiry — all present in capability.capnp:22-53) through a `Text`.
- `module.capnp:201` — `replayEvents @17 (moduleId, fromIndex :UInt64) -> T.VoidResult`. Replay is a state-mutating operation (it re-applies an event log to the module) that returns `T.VoidResult` with no acknowledgement of how many events were applied, whether the log was complete, or what the module's state is after. There is no way to verify a replay.

## Duplicates & overlaps
- `ModuleSandboxConfig`/`LoadLimits` vs sandbox.capnp and `T.Quota`.
- Marketplace/install vs package.capnp.
- `RuntimeBinding { runtimeName, minVersion, maxVersion :Semver }` (module.capnp:255-259) vs `DriverDescriptor.compatibleKernel @5 :Text` (device.capnp:484) — two version-compatibility mechanisms, one free-text.
- `ModuleHealth { healthy, lastCheck, message }` (240-244) vs `T.DriverHealth` (types.capnp:1661-1669) vs audio.capnp's `DeviceHealth` vs device.capnp's `getResourceUsage` — four health structs with different fields.
- `Counter { name :Text, value :UInt64 }` (109-112) vs `T.DriverMetric` (types.capnp:1671-1679) — the same counter shape, two types.
- `Kind.audioCodec`/`videoCodec`/`font` vs audio.capnp's `CodecFamily`/font.capnp's font model — module kinds name codecs and fonts that other schemas model as *resources*.
- `Source.wasm @4 :WasmModuleSource` with `imports :List(Text)`/`exports :List(Text)` — a WASM-specific source type inside the generic `Source` union, so a 2046 module format needs its own source variant (an enum-by-union-member instead of an open `MimeType`).

## Gaps & holes
- **No hot-reload state-transfer contract.** `reload @7 (moduleId, newSource :Source) → LoadResult` has no statement of what happens to existing callers, loaded fonts/streams, or pending requests — the classic hot-reload fork. Every backend invents its own migration.
- **No dependency-resolution semantics.** `ModuleDesc.dependencies @9 :List(T.ModuleId)` and `compose @8 (modules) → composed :T.ModuleId` exist, but nothing says whether `load` resolves transitively, what happens on a cycle, or whether `compose` is a new id space. A 2046 loader with two modules depending on incompatible versions has no resolution rule.
- **No module-failure isolation contract.** `ModuleEvent.failed @3 :ModuleFailure` exists, but nothing states what happens to the *host* or to other modules that depend on it — the same gap device.capnp's `ExhaustedAction` addresses for drivers (device.capnp:583-588), which suggests the mechanism should be shared.
- **No sandbox verification**: `LoadSpec.sandbox @4 :ModuleSandboxConfig` requests sandboxing but nothing confirms it was applied (no result field), and `ModuleState.grantedCapabilities` reports by id without a way to verify the grant against `LoadSpec.capabilities`.
- **`getEventLog @18` is paginated (good), but `replayEvents @17` takes `fromIndex :UInt64` with no upper bound**, so a replay can be requested past the end of the log with no defined behaviour.
- **No signature/provenance on `installFromMarketplace`** while `LoadSpec.verifySignature @1 :Bool` exists on the load path — a marketplace install can bypass verification entirely.

## Zero-cost / eco
- **Correct:** `ModuleDesc.payloadBlob @3 :T.DataHandle` (module.capnp:36) and `Source.blob @1 :T.DataHandle` (129) — module images are bulk and are buffer references. `WasmModuleSource.bytes @0 :T.DataHandle` (263) is correct too. This file passes R2.
- `ModuleEventEntry.payload @2 :Data` (387) — opaque, so event-log replay does not force a schema per event type. Correct.
- `ModuleProfile.topFunctions @6 :List(ModuleFunctionProfile)` (342) — unbounded inline list of named profiles; bounded in practice by symbol count, so acceptable, but it is the one list in the file that grows with module complexity.
- **Idle-power:** `getHealth @9`, `getEventLog @18` (paginated), `getFeatureFlags @20`, `getTenancyConfig @22` are snapshot getters with no subscription. `ModuleSubscription` exists with pull+cancel, so a module monitor can subscribe — but the health/flag/tenancy getters still invite polling.
- No polling-forcing hot path: `load`/`unload` are one-shot and correctly so.

## UX / implementer guidance
- `load @0 (spec :LoadSpec) → LoadResult` returns `state` (which contains the id) *and* `warnings`, but no error — so a load failure is visible only as `state.state = failed`, and the `T.Error` lives in `ModuleFailure`, reachable only via the event stream. A synchronous `load` should return its error synchronously.
- `ModuleState.loadedAt @2 :T.Timestamp` and `memoryBytes @3 :UInt64` are per-module, but `ModuleState` carries no owner or session, so two hosts loading the same module share an id space with no scoping.
- `migrateModule @11 (moduleId, targetKind :Kind)` silently changes a module's kind — a destructive operation returning a new id with no error and no rollback.
- `ModuleEventEntry.type @1 :Text` is an open event-type token while `ModuleEvent` (the live subscription) is a typed union — two event vocabularies, one open and one frozen, in one file.
- `LoadLimits.cpuBudgetNsPerSec @1 :UInt64` (module.capnp:143) is documented well ("100000000 (100ms) means the module can use 10% of one CPU core") but is a nanosecond rate where `T.Duration` is the batch's unit convention.

## Recommended actions
1. **Replace `LoadSpec.capabilities :List(Text)` with `List(Capability)`** (import capability.capnp) and give `ModuleState.grantedCapabilities` the same type. Gain: module authority becomes portable and attenuatable; removes the forbidden permission-string model; `Capability` already carries operations/constraints/expiry, so nothing is invented. Cost: one import + one field type — the single highest-value change in this file.
2. **Delete `ModuleLifecycleHook` / `setLifecycleHook` / `removeLifecycleHook`** (or replace `command :List(Text)` with a capability-gated spawn through kernel/init.capnp). Gain: removes an unauthenticated command-execution path from a module host. Cost: lifecycle hooks must be expressed as capabilities to spawn, which is strictly more correct.
3. **Delete the marketplace, feature-flag and tenancy blocks** (`searchMarketplace @12`, `installFromMarketplace @13`, `ModuleMarketplaceQuery/Result`, `ModuleSortField`, `setFeatureFlag @19`, `getFeatureFlags @20`, `ModuleFeatureFlag`, `setTenancyConfig @21`, `getTenancyConfig @22`, `ModuleTenancyConfig`) and delegate install to package.capnp. Gain: removes ~60 lines of product machinery that no 2046 module loader needs, and stops duplicating package.capnp. Cost: none expressible in the contract — those are application concerns.
4. **Make `load` return its error synchronously** (add `error :T.Error` to `LoadResult`, or return `T.StateOutcome` with the state). Gain: a failed load stops being an event-stream-only fact. Cost: one field.
5. **Specify hot-reload and dependency semantics** (state transfer on reload; transitive resolution, cycle behaviour, version-conflict rule). Gain: removes the two highest fork risks in a module system; without them, no two backends compose. Cost: a short behavioural section.
6. **Add `unknown @N :UnknownEvent` to `ModuleEvent`** and delete `ModuleProfile.topFunctions` (or report it as opaque `Data`). Gain: forward-compatible events and a profile that does not presuppose a symbol table. Cost: one variant, one field.
7. **Replace `ModuleSandboxConfig`/`LoadLimits` with sandbox.capnp's model + `T.Quota`,** and `ModuleHealth`/`Counter` with `T.DriverHealth`/`T.DriverMetric`. Gain: three duplicated concepts collapse to their canonical homes. Cost: three type-reference changes.
8. Leave `Source`'s union, `payloadBlob :T.DataHandle`, `WasmModuleSource.bytes`, `LoadSpec.verifySignature`, `ModuleEventEntry.payload :Data`, the `T.Pagination` usage and `Kind`'s `custom` escape alone: they are the file's sound core, and the trims above make the file smaller and simpler, not bigger.
