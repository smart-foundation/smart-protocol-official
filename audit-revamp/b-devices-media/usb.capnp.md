# audit: `schema/usb.capnp` (602 lines)

## Verdict
**FIX (targeted).** usb.capnp is honest about its scope in its header ("USB is hardware-specific but the Smart Protocol never assumes a particular host controller backend", usb.capnp:6-9), makes correct use of `T.DataHandle` for descriptor blobs and firmware (usb.capnp:171, 82), and correctly declines to enumerate USB classes with a comment that is exactly right ("Raw UInt8 is appropriate for hardware-defined constants; no typed UsbClass enum needed for a timeless protocol", usb.capnp:177-179). That is the right instinct and worth citing as a model. But the file has (a) a **dependency landmine** — it imports `filesystem.capnp` for `MountOptions`, and DESIGN_PRINCIPLES.md:213 has already sentenced filesystem.capnp to be deleted and merged into files.capnp; (b) a **speed enum that cannot express the speeds its own USB4 types advertise** (`UsbCableInfo.maxDataRate :UsbSpeed` and `Usb4Port.maxSpeed :UsbSpeed` max out at `superPlus`, while `UsbSpeedExtended` exists separately for USB4/Thunderbolt rates); (c) **four representations of device speed**; (d) `vfioGroup :UInt32` (a Linux kernel API) in a required field; and (e) an unreachable `UsbHostProvider` whose whole transfer API (control/bulk/interrupt) is dead contract.

## Wire-breakers
- **No compile errors, no ordinal collisions** (verified mechanically).
- `usb.capnp:22, 32` — `using Fs = import "filesystem.capnp"` and `mountDevice @2 (deviceAddress, options :Fs.MountOptions)`. DESIGN_PRINCIPLES.md:213 and filesystem.capnp's own duplicate (`MountOptions` is defined in **both** filesystem.capnp:166 and mount.capnp:163, and filesystem.capnp:583 adds a third, `FsMountOptions`) mean this import is a standing wire-break landmine: if the rewrite wave follows the doctrine and deletes filesystem.capnp, `usb.capnp:32` breaks. `MountOptions` is also still a live duplicate across two schemas.
- `usb.capnp:284` — `UsbCableInfo.maxDataRate @3 :UsbSpeed` and `usb.capnp:389` `Usb4Port.maxSpeed @1 :UsbSpeed`. `UsbSpeed` (usb.capnp:119-128) tops out at `superPlus`. A USB4 Gen 3x2 (40 Gbps), Gen 4 (80 Gbps) or Thunderbolt 5 (80 Gbps) cable or port **cannot state its own maximum speed** — the values exist only in `UsbSpeedExtended` (usb.capnp:131-139), which no field uses. This is a functional hole in the file's own USB4 section, not a style nit.
- `usb.capnp:98-100` — the comment "NOTE: UsbSpeed ordinals start at @1 (ordinal @0 is intentionally unused)" is **false**: the enum is defined `low @0; full @1; high @2; …` (usb.capnp:119-128). An implementer reading the note will map "no speed known" to ordinal 0, which is `low`. A false comment in exactly the place an implementer looks for speed semantics.
- `usb.capnp:505-509` — `UsbHostProvider.controlTransfer @3 (device :UInt32, endpoint :UInt8, setup :Data, dataSlot :UInt32, dataLength :UInt32) -> (result :UInt32)` and `bulkTransfer @4 (…, dataSlot :UInt32, length :UInt32, …)`. The transfer result is a raw `UInt32` and the data slot is a raw index with no buffer ownership, no buffer type, and no relation to the `UsbDeviceAddress.value :UInt64` used by the service. Two device-address spaces (UInt32 vs UInt64-backed) with no documented mapping.

## Duplicates & overlaps
- `MountOptions` imported from filesystem.capnp:166, which duplicates mount.capnp:163, which is itself shadowed by filesystem.capnp:583 `FsMountOptions`. Three definitions, one canonical home claimed by two.
- `UsbPdoRequest` (usb.capnp:471-477) vs power.capnp:50 `negotiateUsbPd @12 (requestedVoltage, requestedCurrent) → UsbPdContract` and power.capnp:290-300 `UsbPdContract` vs usb.capnp's `UsbPowerDelivery.availablePdos :List(UsbPdo)` — USB Power Delivery negotiated in two schemas with two request shapes and two contract structs.
- `getPowerBudget @12 → UsbPowerBudget` (usb.capnp:344-355) vs power.capnp:224-233 `PowerBudget` vs display.capnp:624-629 `DisplayPowerBudget` — three power-budget structs (and nfc.capnp:506's wireless-charging session makes a fourth adjacent concept).
- `UsbAuthentication.blockDevice @2` vs `authorizeDevice @6`/`unauthorizeDevice @7` and `listBlockedDevices @4` (usb.capnp:320-321) — three authorization mechanisms plus a block list, no capability, no relation to `UsbDevice.authorized @11 :Bool` (usb.capnp:114).
- `UsbErrorRecovery { portReset, linkReset, warmReset }` (usb.capnp:480-485) vs device.capnp:583 `ExhaustedAction` and types.capnp:1922 `RecoveryAction` — recovery vocabulary duplicated.

## Gaps & holes
- **No transfer-completion semantics.** `bulkTransfer @4 → transferId` and `pullCompletions @7 → List(UsbTransferCompletion)` exist (in the unreachable provider), but nothing states whether completions are queued, whether `pullCompletions` waits or returns empty, or what happens on overrun. A 2046 isochronous audio device over USB needs a bounded, loss-aware completion stream — the contract has none.
- **No device disconnection semantics.** `UsbEvent.disconnect @1` exists, but nothing states what happens to an in-flight transfer, an open stream, or a mounted device (is `unmountDevice @3` called automatically? does `capture.capnp`'s stream die?).
- **No topology *change* subscription reachable**: `UsbTopologySubscription` exists but only through the unreachable `UsbHostProvider.subscribeTopology @2`.
- **`UsbDeviceQuirks.workaroundFlags @2 :UInt32`** documented as "Bitmask of workaround flags (backend-defined)" — an undefined bitmask. Same anti-pattern as console.capnp's `permissions :UInt32`: the vocabulary (`quirks :List(Text)`) is right next to it, so a client must parse Text and interpret an undefined bitmask.
- **No enumeration of what a mount *does***: `mountDevice @2` returns `T.VoidResult`, so a client cannot learn the resulting mount path (no `T.MountId` returned), and `ejectDevice @4` assumes the device is still present.
- **No power-budget arbitration**: `getPowerBudget @12` reads a budget that no method in the schema can change, so a device that cannot be powered within budget has no negotiation path.

## Zero-cost / eco
- **Correct:** `UsbDeviceInfo.descriptors :T.DataHandle` (usb.capnp:171) — the file's own comment says "Inline when small, buffer-handle when the descriptor tree exceeds 1KB", which is exactly `T.DataHandle`'s documented behaviour (types.capnp:382-387). `updateFirmware`'s payload is a `T.DataHandle`. `UsbTopoNode.configs @4 :List(Data)` are bounded per-USB-spec descriptors, so acceptable.
- **`UsbEvent.device @3 :UsbDevice`** embeds the full 13-field device struct in every event (usb.capnp:457). A hotplug burst of 50 devices ships 50 full device structs — bounded but wasteful; `T.DeviceAddress` would do.
- **`UsbTopology` is a deep recursive structure** — `UsbTopology.rootHub :UsbHub` → `ports :List(UsbPort)` → `device :UsbDevice` **and** `childHub :UsbHub` (usb.capnp:409-438) — nested to the hub-tree depth with no depth bound and no pagination in `getTopology @13`. A deep hub chain is O(ports^depth) nodes copied whole.
- **Idle-power:** `getPowerDelivery @9`, `getPowerBudget @12`, `getCableInfo @11`, `getTopology @13` are polling-only getters with no subscriptions for the things that *change* (cable insertion, PD renegotiation). A 2046 USB-C dock monitor must poll to notice a cable change.

## UX / implementer guidance
- `UsbDeviceAddress.value :UInt64` (service) vs `UsbTopoNode.address :UInt32` and `UsbHostProvider`'s `device :UInt32` — two device-address spaces, both called "address".
- `enumerateDevices @1 → List(UsbTopoNode)` (the unreachable provider) duplicates `listDevices @0 → List(UsbDevice)` (the service) with different node types.
- `getDevice @1 (deviceAddress) → UsbDevice` returns a *device*, while `getDeviceInfo @5 → UsbDeviceInfo` returns `{device, interfaces, descriptors}` — a client must call both and reconcile.
- `UsbInterface.driver @6 :Text` (usb.capnp:185) duplicates device.capnp's `DeviceNode.driverName @6 :Text` with a different field name for the same fact.
- `authorizeDevice`/`unauthorizeDevice` + `blockDevice`/`unblockDevice` + `UsbDevice.authorized` — four spellings of authorization state.

## Recommended actions
1. **Break the filesystem.capnp dependency**: replace `Fs.MountOptions` with a local, minimal `UsbMountOptions` (or take the canonical home in `mount.capnp`/`T.MountId` once the doctrine's merge completes). Gain: removes the landmine under the doctrine's own "delete filesystem.capnp" decision and the third `MountOptions` definition. Cost: one import + one small struct.
2. **Unify speed on a numeric quantity** (`T.Frequency`, or `maxBps :UInt64`) and delete `UsbSpeed`/`UsbSpeedExtended`; repoint `UsbCableInfo.maxDataRate` and `Usb4Port.maxSpeed`. Gain: the file's own USB4 section becomes able to state its speeds; a 2046 160 Gbps link needs no ordinal. Cost: 5 field type changes, 2 deletions — pre-release, ordinal-neutral for consumers who never read them.
3. **Fix the false comment at usb.capnp:98-100** (UsbSpeed ordinals start at **@0**). Gain: stops an implementer from mapping "unknown speed" onto `low`. Cost: one line — highest value/effort ratio in the file.
4. **Reachability**: make `UsbHostProvider` obtainable (e.g. `getHostProvider @N (authority :Capability) -> UsbHostProvider` on a root, mirroring device.capnp's `DriverRegistry`) **or delete the provider block**. Gain: either the transfer API works or the file stops shipping 20 unreachable types. Cost: one accessor, or ~120 deleted lines.
5. **Add verification to `updateFirmware`** (a `T.Version`, a hash, and a signature reference) and gate `authorizeDevice`/`updateFirmware`/`setDeviceQuirks` behind a capability accessor. Gain: firmware flashing stops being an unauthenticated, unverifiable, irreversible operation on any device a client can name. Cost: 3 fields + an accessor layer.
6. **Replace `VoidOpResult` with `T.VoidResult`/`T.Error`** and `UsbEvent.error` with a `T.Error` payload; add `unknown` to the event union. Gain: honest, routable, retryable failures. Cost: two type edits.
7. **Define or delete `workaroundFlags :UInt32`** (`List(Text)` quirks already exists). Gain: removes an undefined bitmask. Cost: one field.
8. Leave `UsbPdo.pdoType :Text`, `UsbEventType`'s core values, `UsbChargingState`, `UsbPowerRole`/`UsbDataRole` and `UsbAltModeProtocol` alone: each is a spec- or physics-closed set with a `custom` escape, and replacing them with open tokens costs consumers the only comparison they have.
