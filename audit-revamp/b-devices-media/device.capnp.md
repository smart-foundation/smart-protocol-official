# audit: `schema/device.capnp` (588 lines)

## Verdict
**FIX (targeted).** The core is genuinely exemplary and must not be rewritten: `T.DeviceId` everywhere, opaque ids, `path` documented as backend-decided and explicitly "not filesystem" (device.capnp:31-32), pagination on `list`, `cancel` on every subscription, `custom`/`other` variants on the Audit-8 additions, and a `properties :List(KeyValue)` escape hatch that deliberately avoids "DRM-vs-other vendor coupling" (device.capnp:75-77). That is the gold-standard pattern applied correctly. The damage is confined to the Audit-8 graft (lines 52-320, lines 443-456): a device-tree catalog acquired pairing, mesh, handoff/continuity, attestation, group management, resource metering, firmware flashing, and a *policy* struct — none of which the device tree needs in order to answer "what exists, which driver owns it, how do I talk to it" (device.capnp:6-11). Those grafts introduced three UInt32 id spaces (`groupId`, `continuityId`, `DeviceGroup.groupId`) that break the file's own opacity rule, duplicated `ThermalState`/`PowerMode`/`DeviceStatus` that other schemas own, and left `notifyDevice`/`updateFirmware`/`setDevicePolicy` ungated. Targeted fix, no rewrite.

## Wire-breakers
- **No compile errors.** No ordinal collisions detected across all 19 assigned schemas (verified mechanically, comments excluded).
- `device.capnp:267` `updateFirmware @29 (deviceId :T.DeviceId) -> T.VoidResult` — takes **no payload**, so it can only mean "the backend knows what to flash", which no contract can guarantee. Paired with `usb.capnp:82` (`updateFirmware(deviceAddress, firmwareData :T.DataHandle)`) the same operation has two incompatible signatures; a client cannot discover which exists.

## Duplicates & overlaps
- `ThermalState` (device.capnp:368-374) ≡ `power.capnp:171-177` — verbatim 5-value duplicate. **Canonical home should be power.capnp** (it is the power/thermal authority) or `types.capnp` alongside `T.TemperatureKelvin`.
- `DevicePowerState` (device.capnp:347-358) overlaps `power.capnp:85-116` `BatteryState` with **incompatible battery scaling**: `device.capnp:353 batteryLevel :Float32 (0.0-1.0, -1.0 = unknown)` vs `power.capnp:88 percentage :UInt32 (0-100)`. A client computing "is my mouse battery low" must know which scale it holds; the two sentinels (`-1.0` vs absent) differ.
- `DeviceFirmwareInfo` (device.capnp:404-415) vs `usb.capnp:81` `queryFirmwareVersion → (version :Text)` vs `camera.capnp:518` `CameraHardwareInfo.firmwareVersion :Text` — three firmware representations, two of them untyped.
- `DeviceAttestation.platformConfig :T.HashOutput` (device.capnp:302) vs `T.KeyFingerprint` (types.capnp:1062) — two hash-carrying structs with different field names for the same idea.
- `initiateHandoff/acceptHandoff/cancelHandoff` (device.capnp:253-256) duplicates session.capnp:87-88 `startHandoff/acceptHandoff` — two handoff contracts with different payload shapes (`DeviceContinuity` vs `SessionHandoff`).
- `notifyDevice @12` duplicates notification.capnp's canonical Notifications service (DESIGN_PRINCIPLES.md:218 already assigns shell-notification duplication as 🟡; the same rule applies one hop earlier here).

## Gaps & holes
- **Hotplug semantics are undefined.** `subscribe @2 (filter :DeviceFilter) → DeviceSubscription` delivers `added`/`removed`/`bound`/`unbound` (device.capnp:164-186) but nothing states the ordering guarantee relative to `list`, whether a device that arrives *and* departs during an unpulled window yields two events, one event, or none, and whether `removed` events carry the last-known `DeviceNode`. Every implementer will invent this, and a client that misses a connect/disconnect pair permanently diverges from the tree.
- **`getDeviceTopology @11 () → (nodes, edges)` is unbounded and unsorted.** On a 2046 machine with thousands of nodes there is no pagination and no root/filter parameter, so topology enumeration is O(system) per call.
- **No driver-escalation contract for a device that acquires new authority.** `trustLevelChanged` events exist (device.capnp:182), but no method documents what a client must do when a device's trust rises mid-session — the classic privilege-escalation fork.
- `getResourceUsage @27` / `getDeviceHistory @10` return snapshots with no error union and no sampling-interval control (contrast `TelemetryConfig.interval` in power.capnp:208), forcing polling.

## Zero-cost / eco
- `list @1`, `getDeviceTopology @11`, `getDeviceHistory @10`, `discoverDevices @7` return `List(DeviceNode)` with **no field-weight limit**; `DeviceNode` embeds `capabilities :List(DeviceCap)` where `DeviceCap.payload :List(Property)` is itself a `List(Text)` pair (device.capnp:131-139). A device with a large property set is a deep nested list shipped whole. Low frequency, so cost is modest — but `getDeviceTopology` is the one call that is unbounded by construction.
- **Idle-power trap:** there is no minimum-interval or coalescing rule on any subscription, and `subscribePowerState @26` + `subscribe @2` mean a component that watches both the tree and power state gets two independent wakeup streams with no batching. On a battery device, two 1 Hz device/power subscriptions = continuous wakeups. No change needed to the shape; a documented "producer MAY coalesce" sentence would let a backend batch.
- No inline bulk payloads (no `List(Float32)`/`Data` pixel or sample buffers) — device.capnp correctly describes *metadata*, not data.

## UX & implementer guidance
- `bind @4 (device, driver :Text)` takes a driver **name**, while `DriverRegistry.register` returns a `T.DriverId` and `findByName` looks up by name (device.capnp:492-505). A client that holds a `DriverId` cannot pass it to `bind` — it must stringify, with no documented name form (the comment's example is `"xhci-pci"`, device.capnp:498). Trap.
- `enum DeviceKind` (device.capnp:59-87) contains `i2c @18`, `spi @19`, `usb @20`, `pci @21`, `gpio @17` — bus types mixed with device *roles*. Bus topology is `BusType` (types.capnp:1685) and `hal.capnp`'s `BusDiscoveryService`; a backend must now answer both, and a client filtering `kind=pci` gets a different set than one filtering the bus service.
- `NumericIds.class/subClass` (device.capnp:126-127) are PCI class codes with no statement that they are PCI-specific, so a non-PCI backend must invent values for required-looking fields.
- `properties :List(KeyValue)` has no key registry, which is correct for an open vocabulary but means `TERMCAP`-style probing: a client cannot learn which keys exist without reading them all.

## Recommended actions
1. **Collapse `ThermalState` and `PowerMode` into power.capnp / `T.PowerSleepState`.** Gain: one power/thermal vocabulary shared by device, display, console and power; removes a verbatim duplicate pair. Cost: 2 enum references repointed in device.capnp; ordinal-neutral (deleting a local type is not a wire change for consumers who never read it).
2. **Promote `groupId`/`continuityId` to `UInt64`-backed typed ids** (or, simpler, delete the group/continuity block entirely — see 3). Gain: restores the file's own opacity rule, removes UInt32 overflow. Cost: a field-type change (major version) — which is free pre-release.
3. **Cut the Audit-8 feature block that is not discovery**: `notifyDevice`, `createGroup`/`addToGroup`/…, `initiateHandoff`/`acceptHandoff`/`cancelHandoff`, `setDevicePolicy`/`getDevicePolicy`, `getMeshCapabilities`, `getResourceUsage`. Gain: removes ~120 lines of duplicated contracts (notification/session/policy/mesh) from the schema whose stated job is "what exists and who owns it"; eliminates the permission-string violation. Cost: the features must move to their canonical homes, which is work — but doing nothing keeps five half-contracts instead of one.
4. **Add one sentence of hotplug semantics** to the file header: ordering vs `list`, and whether a device that appears and disappears between pulls yields both events. Gain: removes the single highest fork-risk ambiguity in the file. Cost: one comment.
5. **Add a `T.Error`-carrying result to `attestDevice @19`** (it already returns a struct; add `error :T.Error`). Gain: honest failure on hardware with no attestation. Cost: one field.
6. **Paginate `getDeviceTopology @11`.** Gain: bounded enumeration. Cost: one `T.Pagination` parameter.
