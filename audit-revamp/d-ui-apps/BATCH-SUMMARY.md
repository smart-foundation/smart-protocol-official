# BATCH SUMMARY — d-ui-apps (18 schemas: compositor, windowmanager, ime, textinput, shell, notification, clipboard, settings, theme, accessibility, surface, app, appindex, package, extension, intent, manifest, cli)

Audit standard: R1–R8 per the brief; every finding cites `schema/<file>:<line>`; pre-release means every breaking fix is free (nothing external consumes the tree). Machine-checked reports cited as E6/E7/E8 come from the repo's own `scripts/validate.py` (read-only run, E1–E8 enforced/ REPORT mode).

## 2. Cross-schema findings (duplicates and forks spanning the batch)

**C1 — The Session handshake exists in five incompatible shapes.** `compositor.capnp:46–75`, `shell.capnp:37–67`, `windowmanager.capnp:29–69`, `ime.capnp:24–43`, plus screenlock's (outside batch). Result enums have 7/4/4/3 values; request bodies differ; capability requests are a *closed enum* in wm (`:32 List(WindowManagerCapability)`), shell (`:40 List(ShellCapability)`), ime (none at all) but an open union in compositor (`:51 List(CapabilityRequest { standard, hotkeys, custom })`). A capability kind invented next year cannot be requested on three of the five services. (Doctrine:258 "unify the handshake pattern, do NOT merge domains" — unification not done.) Also: `session.capnp:35 Session` is a *user* session, not a service session — same identifier, different concept.

**C2 — One surface/commit contract, two divergent implementations.** `surface.capnp:147 FrameSubmission` vs `compositor.capnp:529 SurfaceCommit`: buffer by `T.BufferId` vs by `UInt8 index`; fences `T.FenceHandle` vs `native :UInt64`; `PresentIntent` differs (surface has `periodic/custom`, compositor stops at `atTime`); `DamageOption` is identical twins (138 vs 543). Two `SurfaceRole` enums with different values (surface:323 vs compositor:354). Composites with C4.

**C3 — The accessibility tree is forked three ways.** `accessibility.capnp:195` (canonical, 70 roles, ranges, live regions, reading order) vs `compositor.capnp:668–750` (a reduced copy, 39 roles, no ranges/liveRegion) vs `shell.capnp:1026–1037 ShellAccessibilityTree` (Text ids/roles — a third model). Note the contradictory precedent in-tree: `surface.capnp:4` imports accessibility.capnp and uses `A11y.AccessibilityNode` — the correct pattern exists and the other files ignored it.

**C4 — The audit-7 spatial/zone/animation blocks are copy-paste twins.** `SpatialPose`+`AnchorType` (compositor:1300/1315 ≡ surface:231/246); `DisplayZone`+`ZoneRole`+`ZonePermission`+`InteractionMode` (compositor:1326–1369 ≡ surface:265–299, byte-identical); `EasingType` (compositor:1443 ≡ surface:397) while the canonical `types.capnp:1239 AnimationEasing` sits unused; `ContextBubble`/`BubbleContent` (shell:852/861 ≡ surface:302/312); `CustomQuery` appears in four files (compositor:768, windowmanager:798, shell:637, buffer). Any import of two of these files is ambiguous.

**C5 — Output metadata has three structs in two files.** `compositor.capnp:797 OutputInfo` + `:812 OutputMode` vs `windowmanager.capnp:480 OutputInfo` + `:495 OutputMode` + `:502 OutputInformation` (a third, same file). Outputs cannot be passed between the two services without conversion.

**C6 — Icon payloads are inline in exactly the two app-world schemas that forgot the rule.** `app.capnp:177 AppIcon.data :Data` and `appindex.capnp:271 AppIcon.data :Data` (identical structs) — while `shell.capnp:315`, `package.capnp:176`, `extension.capnp:115`, `notification.capnp:136` all use `T.DataHandle`. A launcher grid copies every icon of every app per render. Same two files also twin `FileRef` (app:119 ≡ appindex:161) while `types.capnp:726 FilePath` exists.

**C7 — Three app taxonomies.** `AppCategory` (app.capnp:192 ≡ appindex.capnp:301, 13 values) vs `ApplicationCategory` (shell.capnp:289, 10 values). An app's category must be mapped at every shell/index boundary; a future category has no ordinal anywhere.

**C8 — Android Intent vocabulary leaked across three files.** `intent.capnp:82–98 LaunchFlags` (FLAG_ACTIVITY_*), `:102 IntentCategory` (incl. `browserCategory`), `:200 firstUser` (RESULT_FIRST_USER); `app.capnp:224 AppLaunchMode` (singleTask/singleTop); duplicated at `appindex.capnp:293`. Activity-stack semantics imposed on every non-Android shell.

**C9 — Authority is modeled five times.** capability.capnp is canonical (target + operations + attenuation/revocation) and `manifest.capnp:99 CapabilityRequirement` copies it correctly — while the batch simultaneously ships: app permission strings + delegation (app.capnp:380, 83, 103), clipboard string-ACLs (clipboard.capnp:184–203), extension capability+scope (extension.capnp:195–210), intent access policies with string action lists (intent.capnp:596–608), settings per-app overrides by AppId parameter (settings.capnp:53). The doctrine bans each parallel model (DESIGN_PRINCIPLES:399; TIMELESSNESS:135–162). No method in this batch takes a per-call `Capability` parameter (verified) — the violation is parallel *models*, not per-method tokens.

**C10 — Store/distribution domain leaked into three local services.** Ratings + moderation + recommendations + ranking weights (appindex.capnp:82–100) vs package's distribution surface; OCI as install path (package.capnp:82, 436) vs `BundleShape.ociImage` + `OciImageManifest` (manifest.capnp:150, 276) vs package's OciImageInstallRequest — one 2026 technology named in two files; supply-chain tooling (SLSA/in-toto/Sigstore) frozen into package.capnp:230, 556.

**C11 — Polling where events belong (eco/zero-waste).** `cli.capnp:13 getJobStatus`, `cli.capnp:53 pollPrompt`, `intent.capnp:226 waitForResult` (pulled per handle), `theme.capnp:2 pullTheme` (manual poll alternative to the subscription), `settings.capnp:40 pullSettings` (deprecated duplicate path). Against the batch's own correct forms: `StreamingOutput` with `finished` (cli.capnp:236–253), `AppIndexSubscriptionFilter.coalesceWindowMs` (appindex.capnp:385), `getSettingsDiff` (settings.capnp:102).

**C12 — Error-model split personality.** The exemplars: `appindex.capnp:172 LaunchResult { success, error :T.Error }`, `package.capnp:132 VerificationResult`, `clipboard`-free... The offenders that claim success on failure: `notification.capnp:30 show`, `package.capnp:23 install`, `app.capnp:49 getAppInfo`, `appindex.capnp:31 getApp`, `settings.capnp:28 get`, `ime.capnp:47 createContext`, `compositor.capnp:92 commit` (Void), `windowmanager.capnp:82 getWindow`. Also bool+prose result patterns: `package.capnp:56 checkCompatibility`-class in extension.capnp:56/84, `clipboard.capnp:76 validateContent`.

**C13 — Named-type collisions with files outside the batch.** `CommandHistoryAnalytics` (shell.capnp:1018 vs cli.capnp:57, different shapes), `GestureEvent` (shell.capnp:805 vs types.capnp:369, different shapes), `Provenance`/`ManifestProvenance` (package.capnp:267 ≡ manifest.capnp:251), `ResourceLimits` (cli.capnp:155 vs compositor.capnp:1429 vs `T.Quota` types.capnp:1776), `ExtensionTrustLevel` vs `T.TrustLevel` (types.capnp:550).

**C14 — Documentation contradicts the schema tree.** `docs/SCHEMAS.md:68–69` says compositor/windowmanager are "Session interface only" (both still carry full flat interfaces, `Compositor`/`WindowManager`, alive); `:166` marks textinput DEPRECATED (file alive, no deprecation marker, never merged); `:167` marks surface DEPRECATED (same); `:71–73, 125–128, 147, 155, 158` name interfaces and types that do not exist (`ClipboardService`, `NotificationService`, `SettingsService`, `ThemeService`, `PackageService`, `ExtensionService`, `AppInfo` in app.capnp, `AppEntry`, `Command`, `CompositorSession`, `ImeSession`, `InputMethod`, `Layer`). An implementer trusting the docs will code against a protocol that isn't there.

**C15 — Machine-reported (validator) defects, batch-wide.** E6 — unions without unknown/custom (16 in batch): appindex:172, compositor:417/427/477/506/556/564/572/630, ime:110, intent:138, manifest:230, package:123, windowmanager:527/551/568. E8 — non-neutral enum `@0` (absent field silently means a paradigm value): ~160 across the batch (compositor 22, windowmanager 19, shell 19, ime 15, intent 9, surface 9, appindex 9, accessibility 9, app 9, cli 5, others 1–5 each). E7's struct-extension-point report is over-broad (it fires on `struct FontSize { points :Float32 }` and `UnknownEvent` itself) — treat E7 as noise except where a struct genuinely gains fields later (see theme audit).

## 3. Top-10 action list (ranked, gain vs cost)

1. **Execute the two doctrine-declared merges: DELETE `surface.capnp` into compositor Session; DELETE `textinput.capnp` into ime Session.** Gain: ends two live forks — the drifted commit paths (C2) and the drifted text contexts; SCHEMAS.md's "DEPRECATED" becomes true. Cost: ~25 methods to port (unique parts listed in each audit); zero importers exist — nothing to migrate. *Free pre-release; expensive forever after.*
2. **Unify the Session handshake** (one handshake contract in types.capnp or a service-session schema; adopt compositor's open `CapabilityRequest { standard, custom }` everywhere). Gain: capability kinds invented any year from now remain requestable on all five session services; handshake code ports between services. Cost: five request/response struct refactors — free pre-release.
3. **Fix the batch's two copy-cost defects on hot paths**: clipboard `getContent/setContent` → `T.DataHandle` (the file's own orphaned `ClipboardContent` proves intent — clipboard.capnp:20/23 vs 98), and `AppIcon.data` → `T.DataHandle` in app+appindex (C6). Gain: image pastes and launcher grids stop copying megabytes per operation; makes `DataHandle` the one rule the batch can be trusted on. Cost: four signatures, one struct retype.
4. **Error-model sweep** (C12): `notification.show`, `package.install`, `app.getAppInfo/getAppState`, `appindex.getApp`, `settings.get`, `ime.createContext` return `{value} | T.Error` results with honest `retryable`. Gain: failures stop masquerading as success across seven services; the appindex `LaunchResult` pattern propagates. Cost: seven signatures — mechanical.
5. **Compositor imports accessibility.capnp and deletes its fork** (C3). Gain: ATs get one tree contract with ranges/live-regions; compositor's reduced copy (39 roles, no ranges) stops being a trap. Cost: one import, ~85 lines deleted.
6. **Delete the flat legacy interfaces** (`Compositor` 187–220, `WindowManager` 214–293) and the `*Paged` ordinals that exist only to patch them (wm:44–48). Gain: removes ~55 duplicated methods and the "which of the two do I call" question; the unbounded originals (wm:73/111/128/160) then become fixable. Cost: nothing pre-release.
7. **Rewrite cli.capnp's command model** for schema-driven generation: `listCommands` + `CommandSpec` binding name → schema/interface/method (params as `T.DataHandle` taught from capnp reflection), reference-gated authority (drop `checkPermission`), job/prompt subscriptions replacing polls (C11). Gain: the `smart` CLI becomes generatable from the schemas — new domains gain a CLI by declaring a schema, satisfying the file's stated purpose; no more per-domain hand maintenance. Cost: the dispatch layer is a rewrite; `execute`/streaming/interactive primitives survive unchanged.
8. **Purge the platform-vocabulary leaks**: Android `LaunchFlags`/`IntentCategory`/`firstUser` + `AppLaunchMode` (C8), `OciCredentials.password` + OCI-first install surface (C10), WASM-first extension runtime + `ScriptAction` (extension.capnp:336), AR/car zones in shell. Gain: the Swap Test passes for alternative compositors/shells/runtimes; no plaintext credentials on the wire; no scripted RCE published as contract. Cost: ~25 methods/enums deleted or generalized to open values.
9. **Consolidate authority into capability.capnp** (C9): delete app's permission-string delegation family, clipboard's string ACL + audit, intent's access-policy service, extension's capability-scope model; per-app settings overrides state that the host gates writes. Gain: one authority path with attenuation/revocation/audit — the doctrine's hard rule; the two-paths-must-agree-forever class of bug disappears from five files. Cost: ~20 methods change or defer.
10. **Fix the machine-reported defects** (C15): add `unknown`/`custom` to the 16 E6 unions; give every non-neutral enum `@0` a neutral sentinel (`none/unknown/unspecified`) in this batch's ~160 cases. Gain: forward compatibility stops depending on consumers' benevolence; absent fields stop silently meaning `light`/`keyboard`/`window`. Cost: mechanical, and the validator now checks it.

**Runner-up (apply opportunistically): trim unevidenced machinery with the "name a consumer or cut" rule** — shell's AR/car/analytics/AI-completion, appindex's ratings/recommendations/moderation, package's mirror/cache fleet, theme's migration, intent's dual recording families, notification's queue/delivery tracking. Each removal deletes a fork surface (implementers would each implement a different subset) at the cost of a feature nobody has yet filed a requirement for; the ordinal is free to re-add when the requirement arrives.

## 4. Contradictions with the doctrine documents themselves (found during this audit)

1. **SCHEMAS.md describes a tree that does not exist** (C14): "Session interface only" for compositor/windowmanager (flat interfaces still fully alive), "DEPRECATED" for textinput/surface (no deprecation performed in the schema files), and a dozen interface/type names that appear nowhere in the schemas (`ClipboardService`, `Command`, `ImeSession`, `Layer`, `AppEntry`, …). The schema tree is normative per its own header comments; the docs disagree with it, and the doctrine's versioning rule ("deprecate, don't delete", TIMELESSNESS:97) is being *displayed* as done while remaining *undone*.
2. **The doctrine's own zero-enum rule is stated as a hard, machine-enforced invariant (ai.capnp:13–15, validator E1) and simultaneously imposed nowhere else** — E1 fires only on ai.capnp, and this batch carries ~220 enums, many failing the 2046 test R1 names (SurfaceRole 24 values, Beam... see per-file audits). Either the rule is batch-wide (and the validator should enforce it beyond ai.capnp) or the doctrine should say "ai.capnp only" — the current middle position leaves every other schema unbounded while claiming a standard.
3. **"Deprecate, don't delete" (TIMELESSNESS:97) is applied as a reason to keep dead code in a pre-release tree.** With zero external consumers, ordinal preservation buys nothing and the cost of keeping two live contracts (surface's drift, textinput's drift) is paid daily by implementers. The doctrine should carve out its own pre-release exception: before first release, BREAKING changes are free.
4. **Validator E7 (struct needs an open extension point) reports `UnknownEvent { typeId, payload :Data }` and `struct FontSize { points :Float32 }` as violations** — it fires on types whose extension mechanism *is* the open value, and on closed measurement wrappers, producing ~1,900 REPORT lines that bury the ~16 real E6 findings. A rule that cannot distinguish `FontSize` from `DragStartRequest` (which genuinely has no extension point) is noise, and noise trains implementers to ignore the validator.
5. **The doctrine requires every union to have `unknown @N :UnknownEvent { typeId, payload :Data }` (TIMELESSNESS:98)**, but the batch's convention settled on `custom @N :Data` (app, appindex, accessibility, ime, settings, extension all use it) — a payload with no type discriminator. The literal rule and the working convention are different contracts; the audits above flag the convention's cost (unroutable unknown events) without pretending the docs match the code.
6. **`docs/SCHEMAS.md` and DESIGN_PRINCIPLES §6 disagree on two verdicts each**: SCHEMAS.md:68–69 asserts cursor/DnD/input routing belong to compositor "Session only" while windowmanager.capnp still carries its own capture/snap/lock-screen surfaces; DESIGN_PRINCIPLES:532–533 rates compositor/windowmanager "Acceptable (no changes needed)" while flagging `Window.pid :UInt32` as a Medium issue at :524 — the pid remains at windowmanager.capnp:316 as this audit verifies.
