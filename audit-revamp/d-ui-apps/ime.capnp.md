# Audit — ime.capnp (473 lines)

## Verdict
**FIX (targeted).** This is the Session-based text-input contract the doctrine designated canonical (DESIGN_PRINCIPLES:211), and its spine — context lifecycle, preedit/commit, method switching, event stream with `custom @9` — is correct and platform-neutral. Three targeted fixes. (1) `InputModality` (273) is a closed enum of input modalities — the one enum in this batch whose value set is guaranteed to be incomplete: a future input modality (BCI beyond "neural", gaze dictation, mid-air haptics) has no ordinal. This is the file's biggest R1 failure, and it sits in *required* positions: `switchInputMethodForContext @21` (95) takes it. (2) The `getVoiceInfo/getHandwritingInfo/getPredictionInfo` + `SpatialKeyboardInfo` query surface (17–20, 390–455) is a per-modality capability museum with no consumer protocol behind it — the actual events arrive through `TextInputEvent`, so the info structs exist to be listed, not used. (3) The merge doctrine ordered (`textinput.capnp` → here) has not happened: textinput.capnp is fully alive and this file lacks its unique pieces (dictation, strokes, suggestions, large-commit). Fix: absorb textinput, open the modality value, trim the museum.

## Wire-breakers
None. Note the header's audit-6 claim "unknown variant renamed to custom for naming consistency" (line 19) is honest but deviates from the doctrine's literal `unknown @N :UnknownEvent {typeId, payload :Data}` shape (TIMELESSNESS.md:98) — see cross-batch note in BATCH-SUMMARY.

## Duplicates & overlaps
- **The entire contract exists twice in the protocol**: `ime.Session` here vs flat `textinput.capnp:22 TextInput` — context create/destroy/enable/disable, preedit/commit, method listing and switching, show/hide keyboard, event subscription. Both are live; SCHEMAS.md:166 marks textinput "DEPRECATED" but the schema file itself carries no deprecation and no merge happened. See textinput.capnp audit.
- `KeyAction` (252) duplicates `compositor.capnp:1033` `KeyAction` (same 3 values).
- `ContextRequest` (100) vs `textinput.capnp:86 ContextRequest` — same 6 fields, two definitions; `SurroundingText` (118) vs `textinput.capnp:127` (different fields: cursor/anchor + offset/limit here vs there); `InputMethodInfo` (171) vs `textinput.capnp:136` (different language model: `List(Text)` vs `List(T.Language)`); `InputMethodState` (181) vs `textinput.capnp:147` (different fields entirely — only here does `active`/`currentMethod` exist). The duplication is not a copy: the two files drifted, so a client written against one gets silently wrong data on the other.
- Voice/handwriting/prediction info (297–386) duplicates the *capability* of dictation already in textinput.capnp (201–265) — whichever file wins, one set must go.

## Gaps & holes
- **Preedit-to-commit lifecycle is per-service, not per-context, for global ops**: `disable @5 ()` and `reset @6 ()` take no context id while everything else does — an app cannot address *which* context it disables without convention. (textinput.capnp:28 per-context `disable` is the correct shape.)
- **No cursor/selection query** on a context: `SurroundingText` carries cursorPosition inbound, but an IME cannot ask the app where the caret is mid-composition.
- **No official "input committed to the wrong context" test**: nothing in the schema tells a backend how to bind a context to a surface after hand-off between outputs (multi-monitor). `createContext` has no surface parameter (textinput.capnp:23 `surfaceId` does). An implementer must guess the binding — a real fork for multi-seat IME routing.

## Zero-cost / eco
- `Stroke.points :List(T.Vec2)` + `pressure :List(Float32)` (360–364): handwriting strokes are the batch's hot bulk input (a stylus generates hundreds of points/second) and they are **inline lists** — copied into every event. `textinput.capnp:231 StrokeData` has the same defect. Stroke batches must be `T.DataHandle` (or the surface commit buffer path) to avoid a per-stroke copy.
- `commitText @12 (text :Text)`: a commit of a pasted document is inline text — textinput solved this with `commitTextHandle @19 :T.DataHandle` (textinput.capnp:49), which must be absorbed here.
- Subscriptions are single-event `next()` (194) — fine for IME rates, acceptable.

## UX & implementer guidance
- `updateContext @3 (id, update :ContextUpdate) -> ()` — returns Void, not `T.VoidResult`, unlike its siblings (the audit-3 note at 15–16 claims these were fixed; `updateContext`, `commitText`, `setPreedit`, `confirmPreedit`, `cancelPreedit` still return bare `()`). An update to a dead context fails silently.
- `TextInputEventFilter` (199) filters by context and kind — good — but `TextInputEventKind` has no `other`; `custom @6` exists only in the *event* union, not the filter. Filtering a future event kind is impossible.
- `PredictionInfo.model @0 :Text`, `VoiceInputInfo.wakeWord @3 :Text`: backend-declared knobs are fine as Text, but they are *published* capability fields that consumers will start branching on (a de-facto enum). `T.StringMap metadata` would keep them open without inviting string comparisons.

## Recommended actions
1. **Absorb textinput.capnp into this file** (contexts per-surface, per-context enable/disable, `commitTextHandle` DataHandle commit, language stack, strokes, suggestions, language list). Gain: one text-input contract — the doctrine's explicit instruction; removes the drifted-twin fork risk that already exists today. Cost: ~10 methods to port; textinput.capnp deleted.
2. **Replace `InputModality` with an open token** (`Text` or T.MimeType-style), and `IMECapability`'s overlapping values with the same token set. Gain: an input modality not yet invented is representable today — the file's own header promise. Cost: `InputMethodInfo.modality` and `switchInputMethodForContext` retype; `IMECapability` collapses into the modality token list.
3. **`createContext` → result union (id + error); `listInputMethods` → paginated.** Gain: context refusal becomes visible; large method lists bounded. Cost: two signatures, matching textinput's existing shapes.
4. **Make `disable`/`reset` context-scoped and all five Void-returning mutations return `T.VoidResult`.** Gain: consistent failure reporting; the audit-3 note's claim becomes true. Cost: 7 signatures.
5. **Strokes and large text via `T.DataHandle`.** Gain: the stylus hot path stops copying point arrays inline — a per-stroke allocation saved on every pen event. Cost: two field retypes on the absorbed structs.
6. **Trim or demote the capability museum** (`getVoiceInfo`/`getHandwritingInfo`/`getPredictionInfo`/`SpatialKeyboardInfo`, 390–455) into one `capabilities :T.StringMap` per method, or delete. Gain: the query surface shrinks 20 methods → 3; unknown-modality backends no longer need stub implementations. Cost: per-modality structured access is lost — accepted, because the events themselves (the actual consumer data) live in `TextInputEvent` and are content-typed already.
