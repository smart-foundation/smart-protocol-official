# Audit — shell.capnp (1037 lines)

## Verdict
**FIX (targeted) — a deletion-heavy fix.** The Session spine (35–67) and its event stream are sound, and the file correctly imports `PowerState` from power.capnp (line 4) — but the body contradicts the doctrine's own instruction (DESIGN_PRINCIPLES:218–220): shell.capnp is a 75-method kitchen sink that *reimplements* notification (82–93, 312–337), clipboard (97–103, 343–366), settings (161–163, 522–550), audio, network, bluetooth, power and brightness surfaces that all have canonical services — each with its own, *different* data model, so the copies have already drifted (shell's `Notification` lacks channels/threads; shell's `ClipboardEntry` has a contentType enum clipboard.capnp doesn't; shell's `ShellSetting` uses domain-less keys while settings.capnp uses domain+key). On top of that sit speculative audit-8/9 feature blocks (AR spatial shell, car split-screen zones, shell analytics, AI completion, handoff, command-history analytics) with no identified consumer. The right shell contract is small: session, launcher façade, tray, portals, aggregation search, and delegation to the canonical services for everything else. Cut to that and the file is exemplary.

## Wire-breakers
None structurally. Semantic breakage risk: shell re-declares `Notification`, `NotificationAction`, `ClipboardEntry`, `TrayIcon`, `SettingValue`-shaped types whose names collide conceptually — and in one case literally (`CommandHistoryAnalytics` at 1018 vs `cli.capnp:57 CommandHistoryAnalytics`, different shapes) — with the canonical services.

## Duplicates & overlaps
- Canonical-service duplicates (the R6 rows): notification, clipboard, settings, audio, network, bluetooth, display brightness, power. Each should be a delegation/façade returning the canonical types, not a re-declaration.
- `TrayIcon`/`TrayMenuItem` (372–396): the tray itself is fine and shell-owned (nothing else in the protocol models it) — keep.
- `SearchResult` (482) vs `system_search.capnp` (not deeply verified here — flagged): shell's universal search should aggregate the canonical search providers rather than define a 4th result type.
- `ContextBubble`/`BubbleContent` (852–869) vs `surface.capnp:302–320 ContextBubbleSurface/BubbleContent` — identical structs, two files.
- `GestureEvent` (805) vs `types.capnp:369 GestureEvent` — same name, different shape (shell's adds `command :GestureCommand`, the shared one has `gesture :TouchGesture`). A genuine name collision with the foundation file.

## Gaps & holes
- **Shell has no contract for what it must do when services are absent** (no notification service installed): `sendNotification`'s failure mode is undefined — the honest contract needs a result union or a documented fallback.
- **No move/resize/ownership boundary with windowmanager**: shell animates/positions windows (shell owns panels) but the protocol never says which service owns a given surface class — the compositor/windowmanager/shell triangle has no arbitration contract. (Overlaps the windowmanager audit.)

## Zero-cost / eco
- `processVoiceCommand @66 (audio :T.DataHandle)` — correct zero-cost for audio; `VoiceShellResultStream.pull (result, done :Bool)` (776) has the structural terminator. Good.
- `pullBatch @75 (stream, maxEvents)` (264) shows the author knew batches matter — the single-event `ShellEventStream.pull @0` (557) should use the same shape.
- Notification/clipboard/tray lists unbounded or offset-less (see R7): every launcher open allocates the full app list; `listAppsPaginated` (176) exists but `listApps @1` remains the "easy" call every implementer will use.

## UX & implementer guidance
- The header (9–33) advertises improvements while the file still ships the duplicated surfaces — an implementer reading the header trusts delegation happened.
- `openFilePicker @46 -> (files :List(PickedFile))` returns a raw list with no cancel/error: the picker is user-driven and cancellable; cancel arrives as an empty list — indistinguishable from "user picked nothing".
- `getDoNotDisturb @9 () -> (enabled :Bool)` (88) vs `setDoNotDisturb` reader/writer pair: notifications' DND now lives in two services (shell + notification channels' `bypassDnd`). Two DND authorities.
- Validator E8: 19 non-neutral enum `@0`s (`utility`, `low`, `active`, `performance`, `launcherEvents`, `text`, …). Machine-reported.

## Recommended actions
1. **Strip every duplicated service surface to a thin façade**: notification, clipboard, settings, audio, network, bluetooth, brightness, power. Gain: one canonical data model per domain (channels, history, structured values, subscriptions all become real); the shell stops maintaining eight drifted copies. Cost: shell methods shrink (~30 removed); shells call the canonical services — which they must anyway to be correct.
2. **Delete the speculative feature blocks with no consumer**: AR spatial shell, car zones, shell analytics, AI completion, handoff, command-history analytics, multi-user, plugin info. Gain: the contract shrinks ~200 lines and every shell implementer faces a surface they can actually complete. Cost: those features become shell-internal or their own schemas if a consumer ever files a requirement — cheap pre-release, expensive after freeze.
3. **Fix `sendNotification` to a result union** (or delegate wholesale so notification.capnp's `show` is the only path). Gain: dropped notifications stop masquerading as sent. Cost: one signature.
4. **Unify `CommandHistoryAnalytics` with cli.capnp** (one struct, one home — see cli audit). Gain: the shell↔CLI shared vocabulary the brief demands. Cost: one type deleted here.
5. **Bound the remaining lists** (`listApps`, `listNotifications`, `getClipboardHistory` with offset, `listTrayIcons`) and make single-event streams batched. Gain: launcher-grid renders stop allocating whole catalogs. Cost: signatures gain `T.Pagination`, consistent with the `*Paginated` twins already present.
6. **Resolve the `GestureEvent` name collision with types.capnp:369** (rename shell's to `ShellGestureCommand` or reuse the shared type). Gain: imports stop being ambiguous. Cost: one rename.
7. **Define the DND authority** (shell getter/setter vs notification channel `bypassDnd`): one owner, the other reads it. Gain: one DND implementation. Cost: two methods deleted.
