# Audit — kernel.capnp (881 lines)

## Verdict
**FIX (targeted, large).** The core boundary — `spawn/exit/signal/getInfo/subscribe` (`kernel.capnp:113-135`), region primitives with backend-decided granularity (`:127-131`), typed IDs throughout, `T.SignalKind` de-duplication (`:17-19`, correct), the single bootstrap capability documented in `boot.capnp:15-18` — is the right contract shape for a microkernel with no scheduler knowledge. But the Audit-7/9 growth welded on machinery the doctrine explicitly rejects: scheduler-state *introspection* (`KernelIntrospectionTarget.scheduler` `:506`), POSIX `zombie` state (`:65`), `ForkFlag` CLONE_* semantics (`:203-210`), live kernel swapping, mesh networking, containers/WASM kernel types, per-CPU/IPI services returning raw addresses. Critically, the header's claim that "internal kernel machinery (scheduling algorithm, page-table structures… interrupt dispatch) belongs to the backend, not the protocol" (`:12-14`) is contradicted by the body: the protocol exposes page-table creation (`via hal`), scheduler query state, and interrupt vectors as first-class methods. The Naledzi bar — implementable with no scheduler knowledge, no format knowledge, zero copies over shared memory, one bootstrap pointer — is met by the core and failed by the accretion.

## Wire-breakers
None: all `T.*`, `B.*` (`boot.capnp` types), and imported `Operation`/`CapabilityService` resolve; ordinals unique across `@0..@37`; the `kernel ↔ boot` circular import (`kernel.capnp:26`, `boot.capnp:22`) is legal Cap'n Proto. (Note: circularity makes the two schemas one compilation unit — a coupling smell, not an error.)

## Duplicates & overlaps
- `TaskState` (`:51-67`) vs `task_scheduler.capnp:104-114` `TaskState` — same name, different members (`pending/queued/completed…`), both enums. Codegen collision; see types audit for the canonical merge.
- `TaskFilter` (`:217-221`) vs `task_scheduler.capnp:145-151` — same name.
- Signal send: `signal @4` (`:117`) vs `process.capnp:27` `kill` vs `signal.capnp:244` `send` — three delivery authorities.
- Capability issuance: `issueCapability @16` (`:140`) vs `capability.capnp:156` `CapabilityService.issue @0`; `capabilities @19` returns that same service (`:145`), so the kernel is its own competitor.
- Service registry: `registerService @36`/`resolveService @37` (`:188-189`) vs `boot.capnp:1104` `serviceEndpoints` vs `discovery.capnp:401` `register` — three registries.
- `boot.capnp:1109` `BootHandoff.handlerTableVaddr :UInt64` keeps a raw function-pointer table in the handoff — contradicting the bootstrap promise "everything is capnp" (`boot.capnp:1088-1089`) that the kernel-side registry exists to replace.

## Gaps & holes
- No contract for observation *after death*: if a task exits, what do holders of its `TaskSubscription` receive, and for how long does `getInfo` keep answering? Every backend invents the window; a supervisor cannot be written portably. Demonstrated fork risk.
- `wait @14` (`:134`) returns `WaitResult` but not *which* waitable fired — `WaitableFilter { domain, topic :Text }` (`:223-226`) is string-matched, so a caller learns "something in domain X fired," not what. For a kernel sync primitive consumed by drivers, that forces polling or backend-specific conventions.

## Zero-cost / eco
- `mapRegion @9` / `shareRegion @12` (`:127-130`) are the right zero-copy primitives — shared regions, not payloads. Good.
- `RegionInfo`/`RegionSpec` carry `backing @3 :UInt64` (`:77`, `:89`) — a raw opaque backing-store id with no declared handle type; should be a typed handle to prevent cross-domain confusion.
- `PerCpuService.get @2 (cpu, handle) -> (address :UInt64)` (`:628`) hands out raw virtual addresses over RPC — a mechanism leak and a type-safety hole (any UInt64 is accepted).

## UX & implementer guidance
- Header comments (`:3-23`) are the best in the batch after `ai.capnp` — and they describe a *smaller* schema than the file contains. The mismatch is the finding.
- `TaskInfo.capabilities @6 :List(CapId)` (`:37`) wraps `T.CapabilityHandle` in a *kernel-local* struct `CapId` (`:45-49`) instead of using `types.capnp:576` directly — a fourth capability-handle spelling in the batch (`CapabilityHandle`, `Capability.id :Data`, `CapId`, `CapabilityGrant.cap`).
- `stage @30` (UserlandImage) / `replace @31` (UserlandImage + args) / `exec @2` (manifestBytes :Data) / `enterUserspace @32` — four overlapping image-install/entry paths with three payload shapes. An implementer must guess which combination is the supported one.

## Recommended actions
1. **Delete the unreachable interfaces and their supporting zoo** (`:270-430` kernel-type/container/unikernel/mesh/extension, `:458-530` introspection, `:532-629` SMP/IPI/PerCpu, `:631-881` swap/AB-slots/proof-artifacts/multi-kernel). Gain: R8 satisfiable; the kernel contract becomes implementable by a microkernel with no scheduler/format knowledge; removes ~450 lines of today's-state vocabulary. Cost: none pre-release (no consumer can even obtain these interfaces).
2. **Rename `TaskState` to the doctrine's universal set** (`active/blocked/suspended/terminated` + `custom`), deleting `zombie`; or better, move the canonical type to `types.capnp` and share it with `process.capnp`/`task_scheduler.capnp`. Gain: passes the Linux→seL4 swap the doctrine itself claims; cost: one enum repointed, free pre-release.
3. **Delete `fork @1` + `ForkFlag`** (`:114`, `:202-215`); keep `spawn @0` as the single creation path. Gain: one portable creation contract; cost: fork-familiarity — a POSIX internal detail, correctly excluded.
4. **Replace `CapOperation`/`CapRights` with `capability.capnp` `Operation`/`Constraints`** (`:164`, `:437-438`, `:798`). Gain: one authority vocabulary; cost: trivial find/replace.
5. **`IpiService.payload`, `IpiEvent.payload`, `exec.manifestBytes` → `T.DataHandle`** (`:577`, `:592`, `:115`). Gain: zero-copy IPI/image payloads; cost: none (DataHandle inlines small payloads already).
6. **Add `unknown` variant to `TaskEvent`** (`:235-243`) and pagination to `listRegions` (`:131`). Gain: R7/R8 compliance; cost: two ordinals.
7. **Define post-death observation semantics** for `TaskSubscription`/`getInfo`. Gain: closes the supervisor fork site; cost: a paragraph of spec — the cheapest high-value fix in the file.
8. **Unify image-install to one path** (recommend `stage @30` + `readEntryContext @33`, delete `exec`/`replace`/`enterUserspace duplication). Gain: one well-known bootstrap flow — the Naledzi "one bootstrap pointer" bar; cost: three ordinals retired pre-release.
